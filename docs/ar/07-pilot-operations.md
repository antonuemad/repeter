# تشغيل تجربة العملاء بالدعوات

النطاق الفعلي: `https://repeater.magic-lap.com/`. الربط يمر بثلاث خطوات منفصلة:
إعداد تطبيق المطور، تفويض صاحب الحساب من معالج **إعداد الروتيشن**، ثم استيراد محتوى
يختاره ومعاينة الجدول. قبول النشر الفعلي خارج نطاق التجربة الحالية. وجود Client ID وSecret
وحده لا يثبت أن حساب عميل خارجي مؤهل للربط.

## منع النشر طوال فترة الاختبار

تعليمات المستخدم بتاريخ 2026-10-15: ممنوع نشر أي شيء على أي صفحة أو حساب طوال فترة الاختبار،
بما في ذلك المنشورات الخاصة وغير المدرجة والتجريبية. اختبارات النشر الآلية تستخدم حسابات
وهمية ومحاكاة API فقط؛ ربط الحسابات وتجهيز المحتوى والنسخ الاحتياطي مسموح.

احتفظ بـ `REPEATER_PUBLISHING_ENABLED=false` في إعدادات الإنتاج. القيمة الافتراضية أيضًا
`false`. القفل يمنع التخطيط والنشر اليدوي والتلقائي واستكمال المنشورات عبر polling، حتى لو
مساحة العمل غير متوقفة أو كانت قواعد الحساب مفعلة. ربط الحسابات والاستيراد يستمران.
تغييره يحتاج موافقة صريحة من المستخدم بعد انتهاء فترة الاختبار، ثم إعادة إنشاء web وworker؛
لا يمكن لزر داخل لوحة التحكم تجاوز هذا القفل. أبقِ مساحات العمل متوقفة أيضًا كحماية إضافية.

## تطبيقات المنصات

| التطبيق | عنوان الرجوع | المطلوب قبل دعوة العملاء |
|---|---|---|
| Google / YouTube / Drive | `https://repeater.magic-lap.com/oauth/google/callback` | [إعداد Google](02-google.md)، تفعيل APIs، تسجيل بريد العميل في Test users، ثم تفويض العميل واختبار قراءة/استيراد مصرح به فقط. |
| Meta / Instagram / Facebook | `https://repeater.magic-lap.com/oauth/meta/callback` | [إعداد Meta](03-meta.md)، صفحة Facebook وحساب Instagram مهني مرتبط، ثم الموافقات المناسبة لحسابات العملاء. |
| TikTok | `https://repeater.magic-lap.com/oauth/tiktok/callback` | مؤجّل باختيار المستخدم؛ لا يُعرض كجزء جاهز من تجربة أول عميل. [دليل الإعداد اللاحق](01-tiktok.md). |

لا تطلب من العميل إرسال كلمة مرور المنصة أو التوكن. يتم التفويض على صفحة المنصة نفسها.
لا تقبل اتفاقيات المطور أو توافق على صلاحيات الحساب نيابة عن صاحبه. أكمل إعدادات التطبيق
ثم اترك خطوة الموافقة لصاحب الحساب. لا تستخدم بيانات اعتماد تطبيق آخر على السيرفر.

قبل كل تجربة ربط: رفض التفويض لا ينشئ حسابًا؛ فشل التفويض يعرض رسالة؛ نجاحه يعرض الحساب
والمنصة الصحيحة. أثناء فترة الاختبار افحص التدفقات بمحاكاة API دون أي نشر حقيقي. بعد انتهاء
المنع وبموافقة المستخدم يمكن تنفيذ قبول النشر على حساب ومحتوى يحددهما. يظل قبول النشر الفعلي
غير مكتمل طوال الحظر، ولا يُستنتج من نجاح اختبارات المحاكاة.

```bash
cd /srv/repeater/app/deploy
sudo docker compose --env-file .env exec -T web python -m repeater.cli integration-status
sudo docker compose --env-file .env exec -T web python -m repeater.cli integration-status --platform youtube
sudo docker compose --env-file .env exec -T web python -m repeater.cli integration-status --testing --platform gdrive --platform youtube
```

الأمر يقرأ الحالة فقط ويعرض عدد الحسابات الفعالة والمحتاجة لإعادة الربط والمنشورات المؤكدة،
دون أسماء العملاء أو التوكنات. يرجع رمزًا غير صفري عند نقص الإعدادات أو الربط أو التنبيهات أو
النسخ، ويظل اختبار النشر الفعلي مطلوبًا حتى لو نجح الفحص.

الفحص الافتراضي يشمل Drive أيضًا. أثناء الحظر يعرض النشر `blocked_by_testing_lock` بدل
طلب اختبار نشر، ويعرض Drive كاستيراد للقراءة فقط. خيار `--testing` يفحص الربط للمنصات
المختارة، وقفل النشر، وحداثة إيصالات النسخ المحلية والخارجية الثلاثة. لا يشترط تفعيل
Telegram الذي أجّله المستخدم، ولا يرسل رسائل أو يتصل بواجهات المنصات. يرجع فشلًا إذا
رُفع قفل النشر أو غابت أي مرحلة نسخ أو ربط؛ نجاحه ليس قبول نشر أو شهادة إطلاق للعملاء.

## النسخ خارج السيرفر

استخدم إعداد rclone مستقلًا، محميًا بوضع `0600` داخل مجلد `0700`، مع remote من نوع `crypt`
يشير إلى مجلد منفصل داخل Google Drive. لا ترفع ملف إعداد rclone أو ملف `.env` أو مفتاح
التشفير إلى مجلد النسخ نفسه. احفظ كلمة التشفير وsalt خارج السيرفر؛ فقدهما يمنع الاستعادة.
إعداد rclone يحجب كلمة التشفير فقط، لذلك تظل صلاحيات الملف ضرورية.

قيم التشغيل في `deploy/.env`، دون أي أسرار في Git:

```dotenv
RCLONE_REMOTE=repeater-offsite:
RCLONE_CONFIG=/srv/repeater/backup-config/rclone.conf
RCLONE_MEDIA_SYNC=daily
```

النسخ اليومي الساعة 03:17 بتوقيت السيرفر. قاعدة البيانات تُنسخ ويُعاد تنزيل أحدث ملف عبر
rclone لفحص SHA-256 قبل تدوير النسخ الخارجية القديمة. الوسائط تُزامن يوميًا مع استثناء
الرفع المؤقت وملفات cookies؛ الحذف محدود وينقل الملفات إلى سلة مؤقتة. المكتبة المحلية
الفارغة لا تمسح مكتبة خارجية ممتلئة.

إيصالات منفصلة داخل `/srv/repeater/backups/status`:

- `last_local_success`: اكتملت نسخة قاعدة البيانات المحلية.
- `last_offsite_db_success`: اكتمل رفع قاعدة البيانات والتحقق من قراءتها.
- `last_offsite_media_success`: اكتملت مزامنة الوسائط.
- `last_success`: اكتملت كل مراحل التشغيل المطلوبة في تلك الدورة.

فحص الاستعادة الدوري: نزّل نسخة من الـ remote المشفر، قارن البصمة، ثم حمّلها في PostgreSQL
معزول بلا منافذ منشورة وبلا worker، وافحص إصدار المخطط وأعداد السجلات. اختبر استرجاع ملف
وسائط ومطابقة بصمته عندما توجد وسائط فعلية. لا تستعد فوق الإنتاج بغرض الاختبار.
لاستعادة كاملة بعد فقد السيرفر تحتاج أيضًا مفاتيح تشفير توكنات التطبيق الأصلية من مخزن
أسرار معتمد؛ عند فقدها يجب إعادة ربط حسابات المنصات، حتى لو استُعيدت قاعدة البيانات.

## التنبيهات

Telegram مؤجّل باختيار المستخدم؛ الإعداد التالي مرجع لوقت استئنافه فقط. فحص التجربة
الحالية يستخدم `monitor.py --no-notify` ولا ينشئ بوتًا أو يرسل رسالة.

أنشئ بوتًا مخصصًا عبر BotFather، وحدد محادثة المشغّل المقصودة، ثم احفظ التوكن ومعرّف
المحادثة داخل `.env` المحمي. لا ترسلهما في المحادثة أو تضعهما في Git. اترك
`REPEATER_TELEGRAM_INCLUDE_DETAILS=false` كي لا تُرسل عناوين الفيديو أو بيانات العملاء.

```bash
sudo docker compose --env-file .env exec -T web python -m repeater.cli test-alert
sudo python3 monitor.py --no-notify
```

نجاح إرسال الاختبار يعتمد على إقرار Telegram API؛ تأكد أيضًا من وصول الرسالة للمحادثة
المقصودة. المراقب يعمل كل خمس دقائق، ويفحص HTTPS وصحة web/worker/db وتأخر المهام أكثر
من 15 دقيقة والمساحة (أقل من 2 GiB أو امتلاء 85%) وعمر النسخ. يرسل حالات العطل والاستعادة
فقط؛ الحالة نفسها لا تتكرر بعد نجاح تسليمها، وفشل التسليم يعاد في الدورة التالية.
غياب البوت لا يُعد نجاحًا في تسليم التنبيه.

المراقب يعمل على السيرفر نفسه؛ انقطاع السيرفر بالكامل يحتاج خدمة مراقبة مستقلة خارجية.
سجل حالته `/srv/repeater/backups/status/monitor.json` وصلاحياته `0600`، والسجلات عبر
`journalctl -t repeater-monitor`. لا توقف خدمات الإنتاج لاختبار التنبيهات؛ استخدم الاختبار
الصريح والاختبارات المعزولة.

## تجهيز أول عميل قبل الدعوة

حالة 16 أكتوبر 2026: العميل لم يُحدَّد بعد. لا تُنشأ مساحة تجريبية وهمية أو أدوار لشخص
مفترض على الإنتاج. أول تجربة مُدارة: شخص واحد، فولدر صغير به 3–5 مواد أصلية يملكها العميل،
وصفحة Facebook واحدة وحساب Instagram مهني واحد إن سمحت أهلية Meta. YouTube اختياري.

1. يجمع المشغّل بريد دعوة Repeater وبريد Google الفعلي ورابط حساب Facebook وروابط الأصول
   المقصودة، ووسيلة دعم وتسليم روابط موثوقة. لا كلمات مرور أو OTP أو توكنات. يحتفظ ببيانات
   العميل خارج Git والسجلات العامة.
2. يجهّز المشغّل Google من **Audience → Test users** في مشروع `repeater-pilot` بعد إذن
   صاحب الحساب. الحالة الحالية External / Testing وحساب المشغّل فقط مدرج. لا يحتاج العميل
   مشروع Google أو Client ID خاصًا به. حساب Workspace قد يحتاج موافقة مسؤول المؤسسة.
3. يراجع المشغّل أهلية Meta قبل وعد العميل بالربط. التطبيق **Repeater** غير منشور حاليًا.
   في تجربة دور تطبيق، تُراجع إمكانية إضافة **Tester** وقبول الشخص للدعوة وحقوقه على
   الأصول المقصودة؛ لا تمنحه Administrator أو Developer أو إدارة Magic-Lap لتجاوز الرفض.
   دور المختبر لا يثبت وحده السماح بأصول شركة خارجية. إذا رفضت Meta ذلك، يتوقف هذا الجزء
   حتى استكمال Tech Provider / access verification وApp Review / Advanced Access اللازمين
   للحالة؛ لا يُنقل ملك العميل إلى مجموعة أعمالنا ولا يُنشر التطبيق كحل التفافي.
4. ينشئ مدير Repeater مساحة مستقلة ومتوقفة ويدعو مالكها عبر [تدفق الدعوات](07-invitations.md).
   يحتفظ القفل العام بقيمته `false` في web وworker. لا يستخدم العميل مساحة المدير المشتركة.

### الموافقات التي يراجعها العميل بنفسه

| الخطوة | ما يوافق عليه العميل | ما لا تفعله الموافقة |
|---|---|---|
| دعوة Repeater | تعيين كلمة مروره وقبول الشروط والخصوصية بعد قراءتهما | لا تفوّض Google أو Meta |
| Google Drive | اختيار حساب Google والسماح بـ `drive.readonly`، مع هوية الحساب وبريده | لا تعدّل ملفات Drive؛ لكن صلاحية القراءة والتنزيل تشمل **كل ملفات الحساب** وليست مقتصرة أمنيًا على الفولدر |
| YouTube، إذا اختاره | هوية الحساب، قراءة YouTube ورفع/إدارة فيديوهاته عبر `youtube.readonly` و`youtube.upload` | لا يبدأ نشرًا أو استيراد آخر 30 فيديو؛ قفل السيرفر يمنع أي رفع/نشر فعلي |
| Meta | قبول دعوة المختبر إن كانت مطلوبة، ثم اختيار الصفحات وInstagram ومجموعة الأعمال المقصودة ومراجعة صلاحيات OAuth | لا تشغّل خطة أو مصدرًا؛ الربط الحالي يطلب صلاحيات نشر أيضًا وليس تفويض قراءة فقط |
| المحتوى | تحديد فولدر أو مصدر يملك حق استخدام محتواه، ثم الضغط على **بدء الاستيراد/المتابعة** صراحة | حفظ الفولدر وحده لا يبدأ الاستيراد، والاستيراد لا ينشر |
| الجدول | اختيار الصفحات والصيغ والأيام والساعة والمنطقة الزمنية وفاصل إعادة المحتوى | معاينة 30 يومًا لا تنشئ منشورات مجدولة ولا تفعّل الخطة |

صلاحيات Meta التي يطلبها الكود الحالي: `pages_show_list`، `pages_read_engagement`،
`pages_manage_posts`، `instagram_basic`، `instagram_content_publish`، `ads_read`،
`business_management`. تشمل عرض الصفحات ومحتواها وإدارة نشر الصفحات وInstagram وقراءة
الإعلانات؛ `business_management` تسمح بالقراءة والكتابة عبر Business Manager API.
Repeater لا ينفذ طلبات إعلانات؛ بعض الصلاحيات تتعلق بأصول
Business Portfolio. لا توصف شاشة الموافقة بأنها «قراءة فقط». رفض صلاحيات النشر المطلوبة
قد يمنع اكتمال الربط الحالي رغم أن النشر نفسه محظور على السيرفر.

Instagram هنا يستخدم **Facebook Login**: حساب Business أو Creator مرتبط بصفحة Facebook،
مع حق صاحب الحساب في إدارة الأصل المطلوب. الحساب الشخصي أو الرابط العام وحده لا يكفي.
قراءة فيديوهات صفحة Facebook تتطلب أيضًا مهمة `MANAGE`؛ حق إنشاء المحتوى وحده لا يثبت
إمكانية استيراد فيديوهات الصفحة. Stories على Instagram مقيدة بحسابات Business في هذا المسار.

### رحلة العميل داخل المعالج

1. بعد قبول الدعوة، يدخل [إعداد الروتيشن](https://repeater.magic-lap.com/setup) ويسمّي الشخص.
2. **الحسابات:** يربط Meta وYouTube إن احتاجه، ويراجع الصفحات المسترجعة ويحدد المقصود فقط
   ثم يحفظ. يسجّل الدخول على المنصة نفسها؛ لا يشارك كلمة المرور مع الفريق. إلغاء OAuth
   يعيده إلى نفس الخطوة؛ الربط لا يفعّل أي نشر.
3. **المحتوى:** يربط Drive، يختار الفولدر أو يلصق رابطه، ويحفظ ثم يبدأ الاستيراد صراحة.
   يشمل الاستيراد الملفات المباشرة المدعومة من فيديو وصور ثابتة عند اختيارها؛ لا يبحث
   داخل الفولدرات الفرعية. يراجع حالات جاهز/قيد التجهيز/فشل حتى تظهر المواد الجاهزة.
   يمكن استخدام الرفع اليدوي إذا لم يناسبه تفويض Drive الواسع.
4. لاستيراد منشورات قائمة بدل Drive، يفتح خيار المصادر الإضافية ثم إعدادات الشخص المتقدمة:
   صفحة Facebook أو Instagram مرتبط ومصرح به → آخر 30 فيديو متاحًا أو الجديد فقط → حفظ
   مصدر متوقف → بدء المتابعة صراحة. هذا المسار للفيديوهات/Reels التي تتيح المنصة تنزيلها؛
   لا يعد باستيراد الصور أو Stories أو carousels أو تنزيل YouTube في النسخة الحالية.
5. **المواعيد:** يبدأ بموعد واحد يوميًا وفاصل إعادة 30 يومًا، ويضبط المنطقة الزمنية.
   **المعاينة:** يراجع المواد والصفحات والتواريخ والصيغ والفجوات والاستبعادات. إذا كانت
   المكتبة 3–5 مواد مع فاصل 30 يومًا، فالفجوات متوقعة؛ تغطية شهر كامل تحتاج مواد مناسبة كافية.
6. ينهي الإعداد مع بقاء الخطة والمساحة متوقفتين والقفل العام مغلقًا. حفظ الإعدادات لا يعني
   تفعيل النشر. قبول هذه التجربة لا يتضمن زر نشر أو رفع خاص أو غير مدرج أو اختبارًا حيًا.

### تشخيص العوائق وقبول التجربة

- Google يمنع الدخول: تأكد من تطابق البريد مع Test users ومن سياسة Workspace. لا تغيّر
  التطبيق إلى Production لمجرد تجاوز الخطأ. في Testing يلزم إعادة التفويض بعد سبعة أيام
  للصلاحيات المستخدمة هنا؛ أبلغ العميل بذلك قبل التجربة.
- Meta يمنع الدخول أو لا يعرض الصفحات: راجع قبول دور الاختبار وأهلية أصول العميل، والحساب
  المستخدم، واختيار الأصول في OAuth والصلاحيات المرفوضة وربط Instagram بالصفحة. توقف عند
  حاجز App Review؛ لا تطلب صلاحية إدارة أوسع عشوائيًا.
- الفولدر فارغ/غير ظاهر: راجع حساب Drive وصلاحية تنزيل الملفات والفولدر نفسه وصيغ الملفات
  المباشرة، ثم رسالة الاستيراد. لا توسع البحث إلى كل مكتبة العميل.
- المعاينة فارغة: راجع المواد **الجاهزة**، الصفحات المختارة والفعالة، توافق الصيغ، المواعيد
  والفاصل. عند تعذر Meta يمكن تجهيز المكتبة؛ معاينة صفحات العميل تنتظر ربط تلك الصفحات.

دليل القبول الفعلي لكل عميل: دخول مساحة مستقلة، ظهور الأصول المختارة الصحيحة، استيراد
المواد المصرح بها دون نشر، ومعاينة مفهومة بالتوقيت الصحيح. يحتفظ المشغّل بقائمة العوائق
والتاريخ ونتيجة كل خطوة دون توكنات أو روابط دعوة. يثبت قبل/بعد التجربة بقاء قفل web وworker
وعدم إنشاء أي `ScheduledPost` أو تفعيل خطة نشر. اختبارات الرفض والاستعادة والعزل والنشر
تظل بحسابات وهمية وHTTP محاكى؛ CI الأخضر ليس موافقة منصة أو دليل قبول عميل حقيقي.
