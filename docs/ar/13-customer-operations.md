# تشغيل تجربة العملاء: التقويم والبريد والفواتير والاستعادة

تحديث 2026-10-16. النشر الحقيقي ممنوع طوال الاختبار، بما فيه الخاص وغير المدرج والمسودات
وحاويات النشر. يجب بقاء `REPEATER_PUBLISHING_ENABLED=false` في web وworker.

## رحلة العميل

القائمة: نظرة عامة ← ابدأ الإعداد ← الأشخاص والخطط ← الحسابات ← المكتبة ← التقويم ← السجل.
المصادر والقواعد والطابور القديم تحت «أدوات متقدمة»، وإدارة العملاء والخدمة والسداد للمشغل فقط.
التقويم يعرض معاينات الروتيشن وحجوزات الطابور بعلامتين مختلفتين. المعاينة ليست سجل نشر.
معاينات الخطط تغطي ثلاثين يومًا من بداية نافذة كل خطة؛ الماضي يعرض الحجوزات المسجلة فقط.

من «تعديل هذه الخانة» يمكن تغيير وقت وجهة واحدة، اختيار بديل جاهز من مكتبة الشخص، أو استبعاد
الخانة. الحفظ يوقف الخطة، يزيد إصدارها ويلغي حجوزاتها التي لم تصل إلى المنصة. لا يمس منشورًا
قد يكون حيًا، ولا يتجاوز فاصل إعادة المحتوى، ولا يبدأ النشر. تعديلات حجوزات خطط الأشخاص تصل
لنفس المحرر؛ الطابور القديم يبقى تحت أدوات متقدمة مع أفعاله المحمية القائمة.

## البريد وHostinger

المرسل `info@magic-lap.com`؛ الخادم `smtp.hostinger.com`، SSL على 465، واسم المستخدم البريد
بالكامل. كلمة المرور غير موجودة بالإعدادات الحالية. جهّزت أداة تحقق دخول فقط، لا ترسل رسائل:

```bash
sudo python3 /srv/repeater/app/deploy/configure_mail.py
```

تُدخل كلمة المرور في الطرفية المخفية، ولا تضعها بالمحادثة أو وسيطات الأوامر. بعد نجاح التحقق،
تحفظ الأداة إعدادات الملف المحمي بصلاحية 600. كلمة المرور المخزنة Base64 لتفادي تفسير محارف
ملف dotenv؛ Base64 ليست تشفيرًا. بعد ذلك يعاد إنشاء web وworker لتحميل الإعدادات مع إبقاء القفل:

```bash
cd /srv/repeater/app/deploy
sudo docker compose --env-file .env up -d --no-deps --force-recreate web worker
```

الدعوات والاستعادة للعملاء تُرسل عبر outbox مشفر، مع صلاحية الرابط وفحص إلغائه قبل التسليم،
إعادة محاولات محدودة، ومسح الرابط المشفر بعد التسليم أو انتهاء الصلاحية. الاستعادة التلقائية لا
تشمل مدير المنصة أو العضو الموقوف أو مساحة مغلقة. الروابط اليدوية تظل متاحة عند غياب SMTP.
إنهاء الجلسات وتغيير الدور يلغيان الجلسات القديمة. لا يعني وجود رسالة بالطابور أنها وصلت.

تنبيهات التطبيق مختصرة: الفئة والعدد ومعرف المساحة ورابط اللوحة. تنبيهات المضيف تعمل مستقلة
عن العامل. مراقبة GitHub تعمل خارج السيرفر كل عشر دقائق على فرع المستودع الافتراضي؛ راجع
سجل External availability monitor للنتيجة الفعلية. البريد من GitHub يحتاج أسرارًا مستقلة:
`REPEATER_SMTP_HOST`, `REPEATER_SMTP_PORT`, `REPEATER_SMTP_USERNAME`,
`REPEATER_SMTP_PASSWORD`. لا تنسخ أسرار المنصات إلى GitHub. لا توجد بيانات SMTP بهذه الأسرار
في هذا الإصدار، ولذلك وصول تنبيه البريد الخارجي لم يُثبت بعد. إشعارات فشل GitHub تعتمد على
إعدادات إشعارات مالك المستودع.

## الباقات والتحويل البنكي

المشغل يحدد أسعار 30 يومًا والعملة والحدود من «الباقات ومراجعة السداد»، مع إعادة إدخال كلمة
المرور. الأسعار وبيانات التحويل لم يحددها المالك؛ طلب الدفع معطل لحين ضبطهما. لا دفع إلكتروني.
`REPEATER_BANK_TRANSFER_DETAILS` هو نص تعليمات التحويل الذي يضبطه المشغل في الملف المحمي.

حدود أولية قابلة للتعديل: أشخاص، حسابات، أعضاء ودعوات نشطة، عناصر مكتبة وتخزين محجوز. المساحات
القائمة تحت legacy ولا تُفرض عليها حدود جديدة بأثر رجعي. العملاء الجدد تحت pilot. الفاتورة
تحتفظ بنسخة من السعر والعملة والحدود عند إصدارها؛ تعديل الباقة لاحقًا لا يغيرها. مرجع التحويل
لا ينشط اشتراكًا: المشغل يتحقق من وصول الأموال ويؤكد ذلك بكلمة مروره. تكرار المراجعة لا يضيف
مدة ثانية. انتهاء الاشتراك يوقف العمل الجديد ويترك القراءة والتجديد متاحين.

التخزين المحجوز يشمل الأصلي والنسخة المجهزة؛ كل عنصر قيد الاستيراد/المعالجة يحجز حتى أربعة
أضعاف أقصى حجم الملف قبل قبوله. هذا تقدير قبول متحفظ، وتستمر حماية مساحة القرص الفعلية.
العضو الموقوف ما زال عضوًا محسوبًا ويمكن استعادة وصوله؛ الإيقاف ليس محو بيانات أو حذف مستخدم.

إغلاق المساحة يحتاج المالك وكلمة مروره وكتابة اسم المساحة. يوقف الخطط والمصادر والدخول،
يفصل بيانات الحسابات محليًا ويلغي الدعوات. لا يحذف محتوى المنصات أو النسخ المحتفظ بها. إعادة
الفتح للمشغل فقط، مع بقاء المساحة موقوفة والحاجة لإعادة ربط الحسابات. مساحة مدير المنصة محمية
من الإغلاق الذاتي. طلب محو البيانات الدائم منفصل عبر الدعم وفق سياسة الخصوصية.

## التحقق من النسخ والاستعادة الكاملة

«حالة الخدمة» تعرض عمر الطابور وإثباتات نجاح قاعدة البيانات المحلية والخارجية والوسائط
الخارجية، وآخر اختبار استعادة. المفقود أو غير المقروء لا يُعرض كنجاح. النسخ ليست إعدادات فقط.

```bash
sudo python3 /srv/repeater/app/deploy/recovery_drill.py \
  --receipt /srv/repeater/backups/status/recovery-drill.json
```

تقرأ الأداة وجهة rclone الحالية، تنزّل أحدث dump وكل الوسائط إلى مجلد مؤقت، تقارن النقل
وتستعيد SQL داخل حاوية PostgreSQL مستقلة `--network none` بلا منافذ أو تطبيق أو worker. تتحقق
من الملفات المرجعية وأحجامها وبصمات الأصول، وتوقف المساحات والخطط داخل النسخة فقط. تنظف
الحاوية والملفات المؤقتة وتكتب إثباتًا خاصًا ووقت نجاح عامًا بلا أسرار. ترفض الحجم فوق 50GB
أو نقص المساحة؛ يمكن للمشغل زيادة حد الحجم بعد فحص سعة المضيف. نتيجة بلا عناصر وسائط لا تثبت
استعادة وسائط عملاء لم توجد بعد؛ اختبارات الملفات الاصطناعية تغطي غياب الملف والتلاعب بالبصمة.

عند كارثة فعلية، يراجع المشغل دليل deploy/README.md وbackup.sh أولًا، ويحفظ إعدادات الإنتاج
ومفاتيح التشفير الأصلية في مكان آمن مستقل؛ SQL والوسائط وحدهما لا يعوضان فقد مفاتيح التشفير.
لا تُرفع أسرار البيئة إلى وجهة سحابية غير معتمدة. التسلسل التشغيلي:

1. أوقف web وworker، وخذ نسخة من الحالة الحالية والبيئة قبل أي استبدال.
2. نزّل dump المحدد والوسائط من وجهة rclone الحالية إلى مساحة استعادة منفصلة؛ شغّل اختبار
   الاستعادة المعزول وتحقق من النتيجة قبل اعتمادها.
3. مع بقاء الخدمتين متوقفتين، احتفظ بمجلد الوسائط الحالي ثم ضع الوسائط المتحققة في مسار
   REPEATER_MEDIA_DIR، بملكية uid 10001. لا تمسح المجلد القديم قبل التأكد.
4. نفّذ `sudo bash /srv/repeater/app/deploy/backup.sh restore /path/to/verified.sql.gz --yes`
   باستخدام إصدار التطبيق المتوافق. هذه خطوة تستبدل قاعدة الإنتاج فعلًا، ولا تُستخدم لاختبار.
5. الأمر يشغل web فقط ويوقف كل المساحات. أبق القفل false؛ لا تستخدم --resume في فترة الاختبار.
   راجع الحسابات والمعاينات ومؤشرات النسخ قبل إعادة العامل. أي نشر وقع بعد تاريخ dump يحتاج
   مراجعة حسابات المنصات لمنع التكرار قبل استئناف مستقبلي مصرح به.

## الاختبارات وحدود الدليل

تغطي الاختبارات PostgreSQL معزولًا: تعديل/بديل/استبعاد وقيود التاريخ، عزل المستأجرين، البريد
والإلغاء والمحاولات، حدود متزامنة، تعليق الوصول والإغلاق وإعادة الفتح، ومراجعة تحويل لا تتكرر.
اختبار السعة يولد 20 مساحة، 60 شخصًا وخطة، 120 حسابًا و1200 بوست نصي، و60 محاكاة بتزامن8.
يقيس المعاينة المحلية فقط؛ ليس ضمان سعة نشر أو SLA. كل HTTP للمنصات محاكى. يظل اعتماد Google
وMeta للعملاء الخارجيين وTikTok المؤجل بوابات مستقلة؛ لا تختفي بسبب نجاح CI أو التقويم.
