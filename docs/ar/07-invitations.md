# تشغيل تجربة العملاء بالدعوات

الوضع الحالي: **تسليم الروابط يدويًا بواسطة المدير**. لا يرسل النظام بريدًا تلقائيًا. الروابط أسرار دخول؛ لا تضعها في تذاكر عامة أو لقطات شاشة أو سجل المحادثات.

## تفعيل مدير المنصة

مالك مساحة العمل ليس مدير المنصة. تفعيل الصلاحية إجراء صريح عبر السيرفر لحساب موجود ومصرّح له فقط، دون تغيير كلمة مروره:

```bash
cd /srv/repeater/app/deploy
sudo docker compose exec -T web python -m repeater.cli grant-operator --email OPERATOR_EMAIL
```

استبدل `OPERATOR_EMAIL` ببريد المدير الفعلي. أمر `create-admin` القديم يظل أداة إنشاء مالك عبر السيرفر؛ لا يمنح صلاحية مدير المنصة الجديدة تلقائيًا. حسابات العملاء تُنشأ بتدفق الدعوات.

## عميل جديد

1. افتح **العملاء** من القائمة الجانبية (`/admin/customers`). هذا القسم لا يظهر إلا لمدير المنصة.
2. أدخل اسم مساحة العميل، بريد مالكها ولغته. ينشئ النظام مساحة مستقلة والنشر متوقف فيها.
3. انسخ الرابط الذي يظهر مرة واحدة وسلّمه للشخص المقصود عبر قناة خاصة معروفة. الدعوة صالحة 72 ساعة ولمرة واحدة.
4. العميل يفتح الرابط، يختار كلمة مرور من 15 إلى 128 حرفًا ويؤكدها، ويقبل الشروط والخصوصية بنفسه. بعدها يسجل الدخول بالطريقة المعتادة.
5. طوال فترة الاختبار الحالية يظل النشر محظورًا، حتى الخاص وغير المدرج. بعد الدعوة يستخدم العميل `/setup` لربط الحسابات واختيار المحتوى ومعاينة الروتيشن فقط. الدعوة لا تمنح موافقة OAuth أو تضيف العميل تلقائيًا إلى قوائم اختبار Google/Meta/TikTok؛ راجع [خطوات الموافقة والتجربة](07-pilot-operations.md#تجهيز-أول-عميل-قبل-الدعوة).

إعادة الدعوة لنفس البريد داخل نفس المساحة تلغي الرابط السابق. لإعادة دعوة مالك لم يقبل بعد: افتح «دعوة مالك أو إعادة دعوته» بجوار مساحة العميل. يمكن إلغاء أي دعوة معلّقة من قائمة المدير. رابط مفقود لا يمكن عرضه مرة أخرى؛ أنشئ بديلًا.

مالك مساحة العميل يستطيع دعوة **محرر** من **إعدادات مساحة العمل ← الأعضاء والدعوات**. المحرر يدير المحتوى والحسابات وإعدادات النشر؛ لا يدير الدعوات أو الاستعادة. البريد المسجل بالفعل لا يقبل دعوة حساب جديد؛ لا تغيّر الدعوة كلمة مرور حساب موجود ولا تضيفه سرًا لمساحة أخرى. تبديل المساحات وإزالة الأعضاء النشطين ليسا واجهتين منفذتين في هذه النسخة.

## استعادة كلمة المرور

1. العميل يفتح «نسيت كلمة المرور؟» ويقدّم بريد حسابه. الرسالة واحدة للبريد الموجود وغير الموجود، ولا يدّعي النظام إرسال بريد.
2. يتواصل العميل مع مدير المنصة عبر قناة معروفة مسبقًا. **الطلب وحده ليس إثبات هوية**؛ لا تعتمد على بريد الطلب أو شخص يطلب نقل الحساب إلى وسيلة جديدة.
3. المدير يفتح **العملاء ← طلبات استعادة الحسابات**، ويتحقق من الشخص، ويؤكد التحقق ويُدخل كلمة مرور حساب المدير لإصدار الرابط.
4. ينسخ المدير الرابط ويسلّمه عبر نفس القناة التي تحقق منها. الرابط صالح 30 دقيقة، لمرة واحدة، وإصداره يلغي روابط الاستعادة السابقة للحساب.
5. العميل يعيّن كلمة مرور جديدة ويؤكدها ثم يسجل الدخول. تنتهي كل جلساته القديمة. تقديم الطلب أو إصدار الرابط وحدهما لا يغيران كلمة المرور.

مالك مساحة العميل لا يستطيع إصدار رابط استعادة لحساب أي عضو، لأن الحساب يمتلك كلمة مرور عامة. الحساب المعطل لا يقبل استعادة. حساب مدير المنصة لا يُستعاد من الويب؛ التعافي الطارئ يحتاج وصول السيرفر الموثوق:

```bash
cd /srv/repeater/app/deploy
sudo docker compose exec -T web python -m repeater.cli issue-password-reset --email OPERATOR_EMAIL
```

هذا الأمر **يطبع رابطًا سريًا**. لا تسجّل مخرجاته في تذكرة أو محادثة. لا يغير كلمة المرور بنفسه، ويخضع الرابط لنفس الانتهاء والاستخدام الواحد وإلغاء الجلسات عند الإتمام.

## التشغيل والحدود

- الروابط تحمل السر بعد `#token=` ليظل خارج مسار طلب HTTP وسجلات nginx/uvicorn. تزيل الواجهة الجزء السري من العنوان، وترسل الرمز في POST محمي بـ CSRF. دون JavaScript يمكن نسخ الرمز من الرابط ولصقه يدويًا.
- لا تُخزّن الروابط الأصلية في قاعدة البيانات أو الكوكي. تُخزّن بصماتها، وتُربط استعادة الحساب بنسخة تجزئة كلمة المرور الحالية. إثبات فتح الرابط في الجلسة الموقّعة ينتهي بعد 10 دقائق؛ أعد فتح الرابط إن انتهى قبل الحفظ.
- حدود محاولات هذه التدفقات محفوظة في PostgreSQL وتعمل عبر إعادة تشغيل التطبيق. طلبات الاستعادة: 3 لكل بريد و10 لكل عنوان شبكة في الساعة؛ فتح/استخدام الروابط: 20 محاولة لكل عنوان خلال 15 دقيقة. قد تحتاج الانتظار إذا كان فريق كبير يشترك في نفس الشبكة.
- عناوين طلبات الاستعادة مشفرة؛ عدادات الحماية تحمل بصمات بمفتاح سري. التنظيف الدوري يحذف الطلبات بعد سبعة أيام، وسجلات الروابط بعد سبعة أيام من انتهائها، والعدادات بعد يوم. سجلات التدقيق تتبع سياسة سجل النشاط.
- نصوص الخصوصية محدثة بإصدار `2026-10-15`. تظهر للمستخدمين الحاليين موافقة جديدة مرة واحدة، ويقبلها كل مستخدم بنفسه.
- عند حادث أمني يحتاج المشغّل تعطيل المستخدم عبر إجراء سيرفر مضبوط (`users.is_active=false`) وإلغاء روابطه؛ إعادة التفعيل تستلزم استعادة كلمة المرور أولًا لإنهاء أي جلسات سابقة. لوحة إدارة الجلسات وتعطيل الأعضاء وإغلاق المساحات واجهات مؤجلة، وليست ادعاءات لهذه النسخة.
