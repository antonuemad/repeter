A seven-dimension adversarial review (security, TikTok/YouTube APIs, Meta APIs, engine, import/media, deploy/ops, UX/compliance) found the defects below. Each was confirmed by an independent verifier who tried to refute it. All were then fixed by six owners with disjoint files, integrated, and re-verified by a second set of skeptics who re-ran the original reproductions and tried to break each fix.

Final re-verification: **81 fixed, 5 partially fixed** (of 86 unique findings), plus the new issues listed below. `Reverify` shows the worst verdict among the verifiers that checked the finding (a finding can be shared by two owners).

## Follow-up: five medium issues closed

The original review results are preserved as history. This follow-up closes all five
medium issues called out in `HANDOFF.md`, plus the related pre-deploy-dump eviction and duplicate
activity leaks. Of the original 86 findings, `deploy-ops-2`, `engine-8` and
`ux-compliance-missed-2` are now fully resolved (84 fixed, 2 partial).

| Issue | Resolution | Regression coverage |
|---|---|---|
| Meta deletion after account purge | Keep a deletion-only user key on retained imports before removing account/source FKs; delete matching files, videos, jobs and notices quoting the video, including released duplicates. | `test_meta_deletion_after_account_retention_removes_imports_and_quoted_activity`, `test_meta_deletion_removes_duplicate_notice_for_an_active_account` |
| TikTok manual retry polls a dead upload | A confirmed retry of a needs-attention post clears old adapter state and remote ids. Scheduled/failed retries keep resumable state. | `test_publish_now_restarts_a_terminal_tiktok_upload`, `test_publish_now_keeps_recoverable_upload_state` |
| Rollback worker starts the wrong image | Printed command carries the restored tag (including arbitrary build tags), paths and worker grace; docs use the same tag. Pre-deploy dumps are kept 30 days without count eviction, and same-second attempts have distinct names. | `test_restore_printed_worker_command_uses_the_restored_release`, `test_failed_rollbacks_do_not_evict_or_overwrite_pre_migration_dumps`, `test_predeploy_dumps_survive_retries_until_the_age_limit` |
| BT.601 sources change colour | Convert the BT.601 matrix and input range to BT.709 limited-range pixels before tagging. | `test_bt601_encode_converts_pixels_instead_of_only_retagging` (smpte170m / bt470bg; limited / full range) |
| Width cap distorts videos | Scale both dimensions by the same factor, accounting for pixel aspect ratio. | `test_picture_filter_preserves_aspect_above_the_width_cap` (5120px square-pixel and anamorphic input) |

The new regressions failed against the original implementation. Final validation: **1673 passed,
8 skipped** in the complete Linux suite (Python 3.12, PostgreSQL 16, ffmpeg 6.1; Docker CLI checks
are unavailable inside the test container). The six new colour/geometry cases also pass against
the macOS ffmpeg. `ruff check`, `ruff format --check`, `bash -n`, `shellcheck -x`, and Alembic
upgrade/check -> downgrade base -> upgrade/check all pass. The initial migration was amended under the repository's
pre-deployment convention; no production schema or service was changed.
